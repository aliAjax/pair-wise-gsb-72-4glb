# 功能开关灰度发布与影响审阅平台

基于 React 的本地可运行前端工程，覆盖功能开关配置、影响评审、依赖分析、灰度时间线、冻结回滚和发布报告。业务数据由 RTK Query 端点驱动，并持久化到浏览器 `localStorage`。

## 技术栈

- React 18 + TypeScript + Vite
- MUI
- Redux Toolkit
- RTK Query
- React Router

## 启动

```bash
npm install
npm run dev
```

默认开发地址为 `http://localhost:18472`。

## 构建

```bash
npm run build
npm run preview
```

## 工作区

- 发布概览：开关采用趋势、环境放量差异、阻断问题和待评审项
- 功能开关：按状态、环境、团队和关键字筛选，进入完整配置编辑器
- 影响评审：逐项检查规则冲突、死代码、指标缺失、实验重叠和客户端兼容
- 依赖关系：依赖影响图、互斥冲突矩阵和降级关系
- 灰度发布：分阶段放量、环境差异、指标守护、冻结和紧急回滚
- 审计与回滚：查询调整、审批和异常事件，记录受影响用户范围
- 发布报告：查看发布明细并导出 CSV

浏览器首次打开时会自动写入示例数据。编辑、审批、灰度和回滚操作会写入 `feature-flag-release-console-v1` 对应的本地存储键。

## 版本化保存与冲突定稿

- 每个功能开关带有单调递增的 `version` 与版本历史；打开编辑器时记录当时版本与完整快照。
- 保存提交携带期望版本号，服务端发现版本已前进时做三方合并：仅一方修改的字段自动收敛，双方都改且值不同的字段列为冲突，评审人逐项选择「采用本页修改 / 采用对端已保存 / 保留打开时旧值」。定稿期间版本再前进会重新报冲突。
- 每次成功提交在审计记录中留存逐字段旧值、新值，冲突定稿额外保存基线值、本页值、对端值与定稿人。
- 未完成的提交写入独立键 `feature-flag-release-console-pending-v1`（提交前 WAL）：刷新、重复点击或本地存储短暂失败后可重试同一笔提交（同一 commitId 幂等），重新打开页面可接续完成；冲突未定稿前主库不落任何数据，单条 `setItem` 原子写入，不会出现半套配置。
- 升级读取没有版本号的历史数据时，按原 `updatedAt` 补建 v1 初始版本，历史审计记录原样保留、继续可查。

## 校验脚本

```bash
node scripts/run-verify.mjs
```

覆盖历史数据迁移、乐观锁、自动合并、逐项冲突定稿、定稿失效、幂等重试、存储失败原子性与挂起提交恢复等场景。
